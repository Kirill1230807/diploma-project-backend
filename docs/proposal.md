# Thesis Proposal

## Попередня робоча назва проєкту

**Українською:** Розробка нативного Android-додатка корпоративного месенджера з наскрізним шифруванням
**Англійською:** Development of a native Android app for a corporate messaging service with end-to-end encryption

## Актуальність та проблематика

Корпоративні месенджери (Slack, Microsoft Teams, Mattermost) стали стандартним інструментом внутрішньої комунікації компаній, проте переважна більшість таких рішень функціонує за моделлю SaaS — дані компанії (включно з конфіденційним корпоративним листуванням) зберігаються на серверах стороннього постачальника. Це створює реальну інженерну та бізнес-проблему: компанії з підвищеними вимогами до конфіденційності (комерційна таємниця, персональні дані співробітників відповідно до GDPR, регульовані галузі) не можуть повністю контролювати свої комунікаційні дані.

Складність проблеми має декілька вимірів:

- **Криптографічний** — реалізація наскрізного шифрування (E2E) вимагає коректного управління ключами, forward secrecy та захисту від MITM-атак; помилки в криптографічному дизайні критично небезпечні.
- **Архітектурний** — необхідність поєднати E2E-шифрування (де сервер не має доступу до вмісту повідомлень) із корпоративними вимогами до контролю (рольова модель, аудит дій), що є конфліктуючими вимогами за своєю природою.
- **Інфраструктурний** — забезпечення можливості розгортання системи на власній інфраструктурі компанії (self-hosted) замість використання хмарного постачальника.

## Сформована ідея продукту

Розроблюваний продукт — це **клієнт-серверна система корпоративної комунікації**, що складається з:

- нативного мобільного застосунку під Android (клієнтська частина);
- серверної частини на базі мікросервісної/модульної архітектури (backend), що обробляє маршрутизацію повідомлень, автентифікацію, керування каналами та ролями;
- системи наскрізного шифрування, інтегрованої на клієнтському рівні.

За архітектурним типом — **розподілена клієнт-серверна система реального часу (real-time messaging system) із вбудованим шаром end-to-end шифрування та підтримкою self-hosted розгортання**, що поєднує риси корпоративного месенджера (на кшталт Slack/Mattermost) із моделлю безпеки захищених комунікаційних платформ (на кшталт Signal).

## Детальний опис функціоналу (Core Features)

1. **Обмін повідомленнями в реальному часі** — надсилання/отримання текстових повідомлень, статуси доставки (надіслано/доставлено/прочитано), індикатор набору тексту.
2. **Наскрізне шифрування повідомлень (E2E)** — реалізація на основі Signal Protocol; сервер обробляє виключно зашифровані дані без технічної можливості доступу до вмісту.
3. **Канали та групові чати** — створення публічних і приватних каналів, керування учасниками, організація спілкування за відділами/проєктними командами.
4. **Рольова модель та керування доступом (RBAC)** — три рівні ролей (адміністратор компанії, керівник каналу, співробітник) з диференційованими правами на створення каналів та керування учасниками.
5. **Аудит-лог дій** — журналювання ключових адміністративних подій системи (створення каналу, зміна ролі, видалення учасника) без розкриття вмісту зашифрованих повідомлень.
6. **Push-сповіщення** — сповіщення про нові повідомлення у фоновому режимі без розкриття зашифрованого вмісту в тексті сповіщення.
7. **Self-hosted розгортання** — пакування серверної частини в контейнеризоване середовище з конфігурацією через змінні середовища, що дозволяє розгорнути систему на власній інфраструктурі незалежно від хмарного провайдера.

## Попередній інструментарій та технологічний стек

### Мови програмування

- Kotlin (Android-клієнт та серверна частина)

### Архітектурні патерни

- MVVM / Clean Architecture (клієнтська частина)
- Шарова архітектура backend (presentation / domain / data)
- Zero-knowledge server (сервер не має доступу до розшифрованого вмісту)

### Фреймворки та бібліотеки

- Jetpack Compose, Material 3 (Android UI)
- Hilt (Dependency Injection)
- Coroutines/Flow (асинхронність)
- Spring Boot (серверна частина)
- libsignal (реалізація Signal Protocol)
- OkHttp WebSocket / STOMP (обмін повідомленнями в реальному часі)
- Room (локальне кешування на клієнті)
- WorkManager, Firebase Cloud Messaging (фонові задачі та push-сповіщення)

### Бази даних

- PostgreSQL (основне сховище: користувачі, канали, ролі, метадані повідомлень)
- Redis (presence-статуси, кешування сесій, pub/sub для масштабування WebSocket)

### DevOps-інструменти

- Docker, Docker Compose (контейнеризація та self-hosted розгортання)
- Android Keystore System (апаратне зберігання криптографічних ключів на пристрої)
